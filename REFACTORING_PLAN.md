### 1.2 Implement permission cache (currently dead code)

**File**: `backend/services/permissionService.js`

The cache module at `backend/utils/cache.js` exports `permissionCache` and `getPermissionKey`, but they are never imported or used. Every WebSocket connection hits MongoDB.

Add caching to `canAccess`:
```javascript
import { permissionCache, getPermissionKey } from "../utils/cache.js";

export async function canAccess(canvasId, userId) {
  const cacheKey = getPermissionKey(canvasId, userId);
  const cached = permissionCache.get(cacheKey);
  if (cached !== undefined) return cached;

  // ... existing DB logic ...

  permissionCache.set(cacheKey, result);
  return result;
}
```

Also implement `invalidateRoomCaches()` properly so revocations take effect within seconds, not 5 minutes. Track keys per room using a `Map<roomId, Set<cacheKey>>`:

```javascript
const roomKeyIndex = new Map();

export const getPermissionKey = (roomId, userId) => `${roomId}:${userId || 'anon'}`;

export const trackPermissionKey = (roomId, cacheKey) => {
  if (!roomKeyIndex.has(roomId)) roomKeyIndex.set(roomId, new Set());
  roomKeyIndex.get(roomId).add(cacheKey);
};

export const invalidateRoomCaches = (roomId) => {
  const keys = roomKeyIndex.get(roomId);
  if (keys) {
    keys.forEach(key => permissionCache.del(key));
    roomKeyIndex.delete(roomId);
  }
};
```

## Phase 3 — Performance & Reliability

### 3.1 Prevent BlockNote editor recreation on provider transition

**File**: `editor/components/Editor.tsx:24-33`

`useCreateBlockNote` runs every render. When `provider` transitions from null → value, BlockNote recreates the editor and loses any text typed during loading.

**Fix**: Don't conditionally pass collaboration config. Instead, render nothing until the provider is ready:

```tsx
const editor = useCreateBlockNote({
  collaboration: {
    provider,
    fragment: ydoc.getXmlFragment("document-store"),
    user: { name: userInfo.name, color: userInfo.color },
  },
});
```

Remove the `provider ? ... : undefined` ternary. The component already guards with `if (!provider || !isSynced) return <Loading />`, so the hook will only ever see a valid provider.

**Caveat**: React hooks can't be called conditionally. `useCreateBlockNote` with `collaboration: undefined` creates a local-only editor first, then on re-render with a provider, it creates a new collaborative editor — losing local state. The guard return prevents rendering, but the hook still runs.

**Proper fix**: Pass a key to the Editor component that depends on `provider` existing:
```tsx
{provider && <Editor key={`editor-${roomId}`} roomId={roomId} />}
```
This ensures the editor component (and its hooks) only mount once the provider is ready.

### 3.3 Fix Excalidraw binding dependency array

**File**: `editor/components/Whiteboard.tsx:45-65`

The binding effect depends on `[api, provider, yElements, yAssets]`. Since `yElements` and `yAssets` come from `useMemo` with `[ydoc]` dependency, they should be stable. But if they do change for any reason, the binding is destroyed and recreated, which causes a flash.

**Fix**: Add a check to prevent unnecessary rebinding:

```diff
  useEffect(() => {
    if (!api || !excalidrawRef.current || !provider) return;
+   // Prevent re-creation if binding already exists for this provider
+   if (binding && binding === existingBindingRef.current) return;

    const newBinding = new ExcalidrawBinding(
      yElements, yAssets, api, provider.awareness,
      { excalidrawDom: excalidrawRef.current, undoManager: new Y.UndoManager([yElements, yAssets]) }
    );
    setBinding(newBinding);
+   existingBindingRef.current = newBinding;

    return () => {
      newBinding.destroy();
+     existingBindingRef.current = null;
    };
  }, [api, provider, yElements, yAssets]);
```

### 3.4 Fix DB index conflict

**File**: `backend/models/Canvas.js`

The `canvasId` field has both a unique index (from the schema definition) and a compound index `{canvasId: 1, ownerId: 1}` that also indexes `canvasId`. The unique single-field index is redundant with the compound index prefix.

```diff
- canvasSchema.index({ canvasId: 1, ownerId: 1 });
+ canvasSchema.index({ canvasId: 1, ownerId: 1 }); // compound covers single-field lookups
```

MongoDB can use the compound index for queries on `canvasId` alone, so the unique index defined inline (line 12) is sufficient. The compound index is still useful for `{canvasId, ownerId}` queries.

No action needed functionally, but note this for awareness.
